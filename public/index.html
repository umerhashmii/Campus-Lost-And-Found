ACID Concurrency Race Condition Demo

Demonstrates InnoDB Row-Level Locking (SELECT ... FOR UPDATE)

Simulates two students (Maaz Malick & Muzammil Rizwan) clicking "Claim" on the exact same found item at the exact same millisecond via concurrent database threads.

Target Item: Found Item #2 (Dell USB-C 65W Power Adapter)
Thread A: Maaz Malick T+0ms
Ready to Run

Awaiting trigger...

START TRANSACTION;
SELECT status FROM found_reports
WHERE found_id = 2 FOR UPDATE;
Thread B: Muzammil Rizwan T+0ms
Ready to Run

Awaiting trigger...

START TRANSACTION;
SELECT status FROM found_reports
WHERE found_id = 2 FOR UPDATE;
💡 Academic Viva Explanation: Both threads executed sp_SubmitClaim simultaneously. The InnoDB lock manager granted an exclusive write lock (X-lock) to the first arriving thread. The second thread was forced into a lock wait state. Once the winner committed, the second thread was evaluated against UNDER_CLAIM and safely aborted, preventing a phantom duplicate claim anomaly.
